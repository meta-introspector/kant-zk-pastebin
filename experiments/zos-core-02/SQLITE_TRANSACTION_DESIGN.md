# SQLite transaction design

Migration `src/001.sql` initializes an empty database through the explicit `init` command. Consumption opens an existing database read/write without the create flag. Connections use the DELETE rollback journal, synchronous FULL, a 750 ms busy timeout, enabled foreign keys and disabled trusted schema. The consumer verifies the expected rollback journal mode and refuses schema/version mismatches, extra schema objects and integrity errors. The schema records an application ID and version 1. There is no legacy state migration.

Authenticate the signature and validate the exact receipt bytes, independent Treasury allowlist and artifact digest before opening the database. Acquire a reserved writer lock with `BEGIN IMMEDIATE` before reading replay state. The lock makes the replay read and both inserts one serialized decision. A competing writer that exhausts the timeout returns a SQLite error and can retry. The balance is derived from the ledger with 100 opening units and a single allowed delta of −7.

Both tables use a composite primary key over the canonical domain and request. The receipts row retains the exact signed message, detached signature as lowercase hex, artifact digest, issuer fingerprint, policy identity and operation. A unique signed message provides an additional constraint. Deferred mutual foreign keys prohibit committing only one side. The guard rolls back when any step fails. A successful commit is required before printing `APPLIED`. A replay releases its transaction before printing `REPLAY`. If the process or response is lost around commit, submit the same authenticated request to determine whether it committed. The recovery test opens a fresh SQLite connection to inspect durable state before submitting again.

Recoverable SQLite errors propagate as errors. Drop attempts rollback and then closes the connection, so a failed request has no live transaction available for reuse. SQLITE_READONLY during the second write and SQLITE_BUSY during writer acquisition are covered in the executable suite. DELETE/FULL and the process-kill results apply to this local SQLite/VFS setup. Device flush behavior and physical power-loss recovery were outside the experiment.
