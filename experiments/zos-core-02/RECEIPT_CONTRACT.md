# CORE-01 receipt contract

The issuer is the unmodified sanitized CORE-01 source in `core01/rebuild/source/seam_step2.rs`. Its staged source-compiled Lean fixture calls JobVerifier `Check.lean` from commit `221cf074aaa3146f41863532a4fd9478dcba044f` using the pinned Lean executable. The fixture is `Good.target`, compared with `Ref.expected` of type `True`. The issuer checks exact output and process status, requires empty stderr and an empty axiom list, and binds source, checker, reference, compiled artifacts and toolchain before and after verification. Compilation failure, `sorryAx`, mismatch and indeterminate output do not reach signing through the issuer gate. See [the original verification contract](core01/rebuild/VERIFICATION_CONTRACT.md).

The bytes signed are ASCII with LF line endings and a trailing LF. The header is `zos.core01b.receipt.v1\nverdict=accepted\nbasis=source-compiled-jobverifier-fixture\n` followed by the exact [pinned descriptor](core01/evidence/descriptor.txt). It fixes the job, verifier and toolchain identities, module, declaration, reference, proposition, axiom policy, replay domain, request, operation and six lowercase SHA-256 bindings in a fixed order. Ed25519 signs the complete raw bytes. The detached signature is exactly 64 bytes. The consumer embeds the trusted public key at build time and accepts no public-key argument. The lab operator establishes trust by taking the public key from the isolated issuer run before the consumer build. The audit fingerprint is SHA-256 over those exact PEM bytes.

The adapter requires byte equality and hashes a snapshot of the supplied compiled artifact bytes. This rejects extra fields, duplicate fields, reordered fields, unknown values and alternative encodings. The operation and DAO authority must independently satisfy the consumer's fixed policy. The signed request authorizes only `treasury:debit:7` under the `treasury` policy. CORE-01 exercised a debit-8 substitution using a generic debit allowlist. CORE-02 pins the only issued operation and rejects debit-8 at the independent policy or exact-message boundary.

The canonical consumption identity is the signed pair `(zos.core01b.synthetic.v1, fixture-request-0001)`. A request string has no separate caller-controlled representation. Signature bytes and issuer identity are audit fields and do not define replay identity. A valid replay returns `REPLAY` with no new effect. This experiment supports one signed fixture request.
