## 1. What Was Built

### 1.1 Dynamic `.so` Tile System

Two standalone `cdylib` crates that produce `.so` files loaded at runtime:

| Tile | Store Path | What it does |
|---|---|---|
| **zos-circuit-tile** | `/nix/store/...-zos-circuit-tile-0.1.0/lib/libzos_circuit_tile.so` | ZK circuit analysis — takes JSON circuit data, returns steps + cost tree |
| **org-tile** | `/nix/store/...-org-tile-0.1.0/lib/liborg_tile.so` | org-mode → HTML rendering via `orgize` 0.10 |

### 1.2 Standard C-ABI Interface

Every tile exports exactly 4 symbols:

```c
int32_t tile_ping(void);                          // health check, returns 1
char*   tile_render(const char* input_json);      // JSON input, JSON output
void    tile_free(char* ptr);                     // free result string
char*   tile_render_json(const char* input_json); // batch JSON I/O
```

### 1.3 FFI Loader (`src/tiles.rs`)

- Reads `TILES_DIR` environment variable (colon-separated list of Nix store paths)
- Scans each path for `*.so` files
- Uses `libloading` to load each `.so` and call `tile_ping()` to verify
- Each loaded tile becomes a `Plugin` in the global `PluginRegistry`

### 1.4 Plugin Architecture (`src/plugin.rs` + `src/plugins/mod.rs`)

- `Plugin` trait: `name()`, `version()`, `can_handle(&str)`, `execute(&str) -> String`
- `PluginRegistry`: `HashMap<String, Box<dyn Plugin>>`
- Built-in plugin: `screenshot`
- FFI tiles: `zos_circuit_tile`, `org_tile`
- Registered at startup in `src/main.rs`

### 1.5 Nix Build (`flake.nix`)

- `combinedSrc` derivation merges bare-mirror flake inputs into a flat source tree
- Each tile has its own flake (`tiles/<name>/flake.nix`) with tile-specific inputs
- Main binary receives `TILES_DIR` with colon-separated store paths to tile `.so` dirs
- All 3 builds (`nix build .`, `nix build ./tiles/zos-circuit-tile#`, `nix build ./tiles/org-tile#`) pass cleanly, zero warnings

## 4. How to Create a New Tile

1. Copy the template:
   ```bash
   bash .forge/skills/tile-system/scripts/create-tile.sh my-tile-name
   ```

2. Edit `tiles/my-tile-name/src/lib.rs`:
   - Implement `tile_render()` — takes JSON string, returns JSON string
   - The output JSON must contain `{"html": "..."}` for the `Plugin` wrapper

3. Generate `Cargo.lock`:
   ```bash
   TMP=$(mktemp -d)
   cp -r tiles/my-tile-name/* "$TMP/"
   cd "$TMP" && cargo generate-lockfile
   cp Cargo.lock /path/to/pastebin/tiles/my-tile-name/
   rm -rf "$TMP"
   ```

4. Build standalone:
   ```bash
   nix build ./tiles/my-tile-name#
   ```

5. Wire into `flake.nix`:
   - Add `my-tile-src` flake input
   - Add `cp -a` line to `combinedSrc` derivation
   - Add store path to `TILES_DIR` in `kant-pastebin` derivation

6. Rebuild main binary:
   ```bash
   nix build
   ```

## 6. Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| `cssparser` path dep not found | Nix store missing submodule content | Ensure bare mirror has the pinned commit — push from working tree |
| `zkperf-macros` not found in offline build | `Cargo.lock` stale — missing zkperf deps | Regenerate: `cargo generate-lockfile`, commit, `nix flake lock --update-input <name>` |
| Tile `tile_ping` returns 0, tile not loaded | `.so` built but symbols not exported | Check `crate-type = ["cdylib"]` in `Cargo.toml`, `#[no_mangle]` on all 4 symbols |
| `combinedSrc` creates hash-named subdirs | `cp -a` copies source dir INTO existing target dir | Use `rm -rf $out/target; cp -a ${src}/. $out/target/` |
| Build uses stale derivation | flake.lock is old | `nix flake lock --update-input <name>` or `nix build --refresh` |
| `cargo check` passes but `nix build` fails | Nix uses vendored deps, not ~/.cargo | Check `Cargo.lock` has `checksum` fields — regenerate if missing |
| `allowBuiltinFetchUrls` not recognized | Older nixpkgs version | Remove `allowBuiltinFetchUrls`, use `builtins.fetchTarball` instead |
