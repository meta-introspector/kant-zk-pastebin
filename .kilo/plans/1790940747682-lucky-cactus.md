# Helia (js-ipfs) in the browser for Kant Pastebin

## Goal

Give the browser a real in-browser IPFS node so P2P file sharing works without a
local kubo daemon being the source of truth. The existing relay room carries
coordination (kzcid records, presence); Helia carries the bytes.

Confirmed decisions:
1. **Ship Helia Nix-bundled vendored ESM** into `web/vendor/js/` — no CDN.
2. **Full libp2p dial to the running kubo** — websockets + webtransport transports.
3. **Put blocks under pre-computed CIDs** — match by construction, no importer guesswork.

## Steps

### 1. Vendored bundle input

Create `web/vendor/package.json` (module deps only, private):

```
helia, @helia/blockstore-idb, @helia/interface, multiformats,
@libp2p/websockets, @libp2p/webtransport, @libp2p/circuit-relay-v2,
idb-keyval   |   dev: esbuild
```

`web/vendor/src/entry.js` re-exports **only** the surface `web/` needs: `createHelia`,
`blockstoreIDB`, `CID`, `websocket`, `webtransport`. Keeps the bundle from dragging in
bitswap/DHT/routing we do not call.

Build script: `esbuild src/entry.js --bundle --format=esm --splitting --outdir=js
--platform=browser --target=es2022`. Splitting output is fine — relay already serves `.js`.

### 2. Nix derivation

Add to `flake.nix` a `heliaVendor = pkgs.buildNpmPackage { … npmBuildScript = "build";
installPhase = "cp -r js $out/"; }`, exposed as `packages.helia-vendor`. First build prints
the real `npmDepsHash`; fill it in. Add `packages.default` unchanged. Do **not** disturb the
existing crane/nora cargo vendor path.

### 3. Rewrite `web/kant-helia.mjs`

```js
import { createHelia, blockstoreIDB, CID, websocket, webtransport, KUBO_PEER_ID, KUBO_ADDRS }
  from "./vendor/js/entry.js";
```

- `heliaNode()` — lazy singleton. `createHelia({ libp2p: { transports: [websocket(), webtransport()] },
  blockstore: blockstoreIDB() })`. Cache the in-flight promise, not the resolved node, so
  concurrent callers share one init.
- `heliaDial()` — `node.libp2p.dial(KUBO_ADDRS[0])`, best-effort, never throws into callers.
- **`heliaPut(bytes)` — the CID contract:**
  1. `cid = await cidOf(bytes)` (WASM/JS ground truth)
  2. `await node.blockstore.put(CID.parse(cid), bytes)`
  3. `await node.pins.add(cid)`
  4. return `cid`
  Matches by construction — no `content.add()`, so no codec/chunking ambiguity.
- `heliaCat(cid)` — local blockstore → libp2p bitswap (via the kubo dial) → null.
- `heliaAvailable()` — `heliaNode()` truthy.

### 4. Multi-chunk puts

For artifacts > 256 KiB the root is a dag-pb block the importer would normally build.
Export the existing private `unixfsRoot()` + `cidIdentity()` in `kant-ipfs.mjs` as
`unixfsRootBlock(links, filesize, blocksizes)`, then in `heliaPut`:

- per chunk: `blockstore.put(CID.parse(await rawCidOf(chunk)), chunk)`
- root: `blockstore.put(CID.parse(await unixfsCidOf(bytes)), unixfsRootBlock(...))`

Single-chunk path stays the 3-step `heliaPut`.

### 5. Wire into `kant-ipfs.mjs`

`ipfsAdd`: helia first (return the CID only when it equals `cidOf(bytes)`), then existing
kubo RPC, then null → caller embeds base64. The equality guard stays as a belt-and-braces
check even though step 3 makes mismatch impossible.

`ipfsCat`: helia first, then existing gateway fetch, then null. Keep the existing
`timeoutMs`/`gwBase` params intact — callers depend on them.

`kant-file-ipfs.mjs` needs **no change** — it already delegates to `ipfsAdd`/`ipfsCat`.

### 6. Config + UI

- Add kubo peer id / dial address to `web/kant.config` (already exists) rather than
  hardcoding; default to the values above.
- `p2p.html`: replace the probe with `heliaNode()` + peer-id + `heliaDial()` result;

### 7. Tests

- `web/helia-test.mjs` — **CID compatibility gate**: for probe sizes 1 / 2000 / 262144 /

  round-trips the exact bytes. Must pass before Helia is trusted.
- Extend the existing Playwright spec (or add `mesh-test/mesh-helia.spec.js`) — serve
  `web/` over HTTP, load `p2p.html`, assert the helia status line reads ready.
- Add the gate to `pipelight.yml` (created earlier) as a stage-17 step.

### 8. Verify

- `cargo test --release --manifest-path pastebin-wasm/Cargo.toml` — CID vectors unchanged
- `node web/helia-test.mjs` — the gate

## Risks

- **Bundle size**: Helia + libp2p bundles to roughly 1–2 MB. Acceptable (kant_kernel.wasm
  already ships), but it is a real change to `p2p.html` load time. Measure and report.
- **`npmDepsHash`**: needs one online build to resolve; if `nora`'s npm endpoint is not
  reachable, use registry.npmjs.org. Flag which one was used.
- **Dial address drift**: the libp2p.direct DNS name and circuit-relay address change if
  kubo restarts. Keep it in `kant.config`, treat dial failure as non-fatal (falls back to
  the gateway path that already works).
- **Chunked dag-pb framing**: reusing the JS `unixfsRoot()` keeps the pinned framing, but
  the >256 KiB path is new and only covered by the new gate — verify it against kubo with
  `ipfs add --cid-version=1 --raw-leaves` on a >256 KiB file.
